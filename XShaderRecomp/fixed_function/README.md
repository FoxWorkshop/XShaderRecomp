# Fixed function ubershaders

Host shaders that basically emulate the D3D8 fixed function pipeline through modern HLSL, plus a generator
that turns the states a game uses into specialized variants.

They were originally written for [Shadow Recompiled](https://github.com/FoxWorkshop/ShadowRecomp),
but nothing in them is game specific. They use the same push constants (and
shared constants) layout as the XShaderRecomp templates in `template_vs` and
`template_ps`, so any Xbox game can use those.

## Motivation

[Sewer yapping abound.]

Alright, some things to unpack here.

So, originally Sora wrote an ubershader for the fixed function vertex shader and
the fixed function pixel shader.

Compatibility wise, it ran great. However, there was one problem, we observed
significant performance issues on various GPU setups.

For instance, in Shadow Recomp covering your whole screen with a torch in Cryptic Castle at
full screen could tank your FPS from 300 to 60 (real number).

After some investigation I found that the cause of this was due to the fact
we did in fact, use Ubershaders. Our pixel shader in particular was being a huge
bottleneck; especially when rendering transparent objects to the screen/.

Now; I'm no GPU programmer myself but I do know and hear a few things.
So; GPUs do something called 'SIMT'. Every instruction is ran on every thread.

Now; because the original Ubershader had to cater for any configuration
that the native code would give it; the shaders were in fact, pretty branchy.
(And that's bad!)

Under SIMT, all branches would always be executed, some being discarded.
Even when not discarded, extra work was being done when it didn't really need
to be.

## What is this?

Therefore, I attempted to solve the issue. The fix is here.

I turned the ubershaders into generics/templates; by essentially abusing `#define`(s).
This is what this code is. Then I runtime logged every single
input combination that the game requested to the vertex and pixel shaders.

After, I identified every case (e.g. branch, constant), that could be eliminated
out; and turned these into template parameters. Every combination the game
can send is now its own unique shader, e.g. variant_000.hlsl.

At runtime, we hash the inputs, and then dispatch to the relevant shader.

## Files

Relevant source code:

The full ubershaders:
- `FixedFunctionVertexShader.hlsl`
- `FixedFunctionPixelShader.hlsl`
Ran if your game requests a combination/state we did not log.

Shared impl used in shaders:
- `common_fixed_vs.hlsli`
- `common_fixed_ps.hlsli`

Autogenerated/derived shaders in `fixed_function_pixel_shader/` and `fixed_function_vertex_shader/`:
- `state.hlsli`: has constants/defines for shader templates.
- `generate.py`: translates logged combinations to variants.
- `states.jsonl`: are the logged combinations.

Shared tools:
- `variant_hash.py`: rapidhash in Python, used for the runtime keys.
- `XShaderRecompFixedFunction.cmake`: compiles the shaders and checks that
  the generated variants are not stale.

## Using it in a recompiled game

The game will keep the generated output since it's built from its own states. 

So simply add in CMake:

```cmake
include(".../XShaderRecomp/XShaderRecomp/fixed_function/XShaderRecompFixedFunction.cmake")

xsr_add_fixed_function_shaders(
    TARGET MyGame
    DXC ${DXC_PATH}
    DXIL ${MY_GAME_D3D12}
    DXIL_MACRO MY_GAME_D3D12
    OUTPUT_DIR "${CMAKE_CURRENT_BINARY_DIR}/fixed_function"
    PIXEL_GENERATED_DIR "${CMAKE_CURRENT_SOURCE_DIR}/gpu/generated/fixed_function_pixel_shader"
    VERTEX_GENERATED_DIR "${CMAKE_CURRENT_SOURCE_DIR}/gpu/generated/fixed_function_vertex_shader"
    PIXEL_STATES "${XSR_FIXED_FUNCTION_DIR}/fixed_function_pixel_shader/states.jsonl" "${CMAKE_CURRENT_SOURCE_DIR}/gpu/pixel_states.jsonl"
    VERTEX_STATES "${XSR_FIXED_FUNCTION_DIR}/fixed_function_vertex_shader/states.jsonl" "${CMAKE_CURRENT_SOURCE_DIR}/gpu/vertex_states.jsonl")
```

And that should be it.

Notes:
- `*_STATES` defaults to the shared file `states.jsonl`. Other games will most likely
  get the same states, so keep those in the list and add your own file right after it.
- `DXIL_MACRO` is the define that guards the DXIL blobs in the generated
  catalog headers. It defaults to `XSHADER_RECOMP_DXIL`.

## How selection works

A lookup follows this sequence:

1. Capture the shader's inputs.
2. Normalize them (vertex only; see below).
3. Hash the state and binary search the generated table.
4. Return a stable, generator output unique key, or key zero for the generic fallback.

We go YOLO mode, and don't check for equality on the hash.

There's only ~338 states; 64-bit hash collision on them is basically 'no chance'.
I'm more likely to be hit by a meteor. In Shadow Recomp, we never hit collision during data
collection; and that was a run of the whole game yielding only 338 entries.

Anyway, that 'key' we get from hashing the state is then used in the shader
pipeline cache file. It's also used to get the actual shader.

All of the lookups are binary searched; so they're basically 6 if statements
O(log(N)). Since there's typically only ~35 lookups per frame, I've not yet
gone the 'perfect hash' route.

## Regenerating variants

The recompiled game (host) ships the generated variants, so a regular build never runs Python.
After changing a states file or a generator, you can run the command that CMake prints, e.g:

```bash
python3 fixed_function_pixel_shader/generate.py \
    --states fixed_function_pixel_shader/states.jsonl my_pixel_states.jsonl \
    --output <game>/generated/fixed_function_pixel_shader \
    --dxil-macro MY_GAME_D3D12
```

You can then commit the changes. CMake
sets SHA-256 hashes of each input and output in `manifest.cmake`, and then stop
at configure time when they no longer match.

## Performance

I'm not a crazy person and didn't make a variant for every single possible
combination. Being clever about this here.

(Ok I'm crazy, but not silly- maybe, uwu :3)

For instance, we observed 338 pixel shader states, but only created 75 derivatives,
based on the input parameters that actually matter. i.e. those affecting branches,
or those where a constant value would be used that could be optimized out
by the shader compiler.
